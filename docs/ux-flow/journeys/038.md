# STORY-038 — Retime a camera movement

Evidence: `038-screens/01-timeline-empty-scene.png`, `02-timeline.png`, `03-retimed.png`, `04-opened-editor.png`; live pass 2026-11-08.

## Friction Scorecard

| Metric | Measured |
|--------|----------|
| Interface actions | 5 (open Timeline, edit Start, edit End, Apply timing, verify) |
| Ideal | 3 |
| Screens | 1 (Timeline) + optional jump to workspace |
| Needless decisions | 1: Apply timing is a separate commit after typing two fields |
| Re-entry | Start/End must be retyped even when only duration changes; there is no duration field |
| Confirmations | None; Edit/Delete are one click away on the same row |
| Dead ends | Scene-scoped: switching scenes silently changes the visible rows; no note that other scenes have effects |
| Hesitations | Row labels switch from workspace `Start + Duration` to Timeline `Start/End`; the empty-state for a scene without effects was not observed because the captured scene had fog |

## Take-away Pass
- A row packs name, scene time range, bar, Start, End, Apply timing, Edit, Delete and an error slot. Dense but each element supports retiming or navigation.
- Ruler and bar are redundant seek targets (bar seeks to effect start, ruler to quarters). Both are useful at different granularities; keep both.
- The `Track` / `Timing · seconds` column headers do not identify which lane is camera vs atmosphere; the left cell subtitle does (`Camera · 0s – 2s`).
- Timeline lives under the same preview as every other workspace but is labelled `Timeline` in the top nav and `Movement timeline` in ARIA — minor naming drift.
- Edit navigates to the object's home workspace, which is the right canonical editor; keep this as a shortcut rather than a parallel form.
- Delete sits beside Apply timing with equal visual weight and no confirmation inside Timeline (the workspace delete does confirm). Confirmation budget is inconsistent across surfaces.

## The Simpler Version
1. Drag the bar to retime, or type Start/End and see the bar update live.
2. Release/blur commits; no separate Apply timing button.
3. A row's Edit opens the canonical editor.
4. Scene scope is stated: "This scene · 1 effect. 2 in other scenes."

Concrete changes: commit timing on blur/Enter (or keep Apply but disable it until a change); add a duration readout; unify labels with workspaces (Start + Duration or Start + End, not both); confirm delete consistently; state scene scope and link other scenes' effects.

## Clarity Issues
- `Start`/`End` vs `Start`/`Duration` across surfaces.
- Error slot is empty and invisible until an error, so failed applies are only explained after the fact.
- Playhead is a thin line with no time tooltip.
- Legacy rows are display-only with no "why" affordance; the label `Legacy` is used without explanation in Timeline.

Verdict: acceptable
