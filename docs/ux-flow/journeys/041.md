# STORY-041 — Export one scene

Evidence: `041-screens/01-export-panel.png`, `02-export-result.png`, `03-service-error.png`; live pass 2026-11-08.

## Friction Scorecard

| Metric | Measured |
|--------|----------|
| Interface actions | 3 to start (open Export, choose quality if needed, click Export Current Scene) + wait + download click |
| Ideal | 3 |
| Screens | 1 |
| Needless decisions | 2: current vs all when only one scene is meaningful; Standard vs High before knowing the trade-off in file size/time |
| Re-entry | None; scene name and duration are shown |
| Confirmations | None (correct; export is non-destructive) |
| Dead ends | After Ready, the next step is a second click on `Download …`; no auto-download and no "open folder" affordance |
| Hesitations | Two equally weighted tan primary buttons; the heading `MP4 EXPORT` repeats the left nav label; no indication of how long an export will take |

## Take-away Pass
- `Quality` dropdown: one control, sensible default, but its consequence is only "smaller, faster" vs "sharper, slower" — no estimated size or duration.
- Two symmetric sections each restate scope, duration and a primary button. With one scene, both produce the same video. This is the clearest single simplification in the app: one Export action plus a scope selector.
- Repeated information: `MP4 EXPORT` appears twice (workspace caption and inspector heading); current scene name/duration appears here and in the Story list/preview total; the FFmpeg/FFprobe requirement appears as a note below the actions, after the user has already clicked.
- Error state (03) is good: red message names the cause and gives an actionable command (`npm run dev:studio`) plus "reload". It omits the consequence — unsaved work will be lost on reload. That matters because Save is manual.
- Progress is a native `<progress>` bar plus status text; both are needed for long exports. The status appears below the button, which is the right place.

## The Simpler Version
1. Open Export; see one scope selector (Current scene / All scenes, current pre-selected) and one quality selector.
2. Click **Export**; progress appears in place.
3. On Ready, the download starts automatically; the panel keeps a **Download again** link.

Concrete changes: collapse the two sections into one action with a scope radio/segment; state the prerequisite before the button (or detect and disable with an explanation); auto-download on ready; add unsaved-work warning to the reload instruction; show estimated duration/size next to quality.

## Clarity Issues
- `Export Current Scene` / `Export All Scenes` use button labels as section headings, so the same phrase appears twice in each section.
- "Verified" in the success message is not explained (it means the MP4 was probed).
- Quality labels describe trade-offs but not the target (1920×1080, 60 fps) or file format.
- The export-service error is the only place the app explains the local architecture (`dev:studio`, FFmpeg); setup knowledge lives outside the product.

Verdict: acceptable
